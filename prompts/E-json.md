## Use the registry

The registry is the source of truth for a component's props, slots, enum options, defaults,
and import specifier.

```sh
YOSEGI={YOSEGI_BIN}
node $YOSEGI component list --data-dir .yosegi --quiet
node $YOSEGI component inspect "src/components/post-card#PostCard" --data-dir .yosegi --quiet
```

`component inspect` accepts several ids at once. Confirm every component's props there
before you write it. You may also read `src/` if you want to; nothing forbids it.

## Your route

**Go through Screen JSON.** This is Yosegi's Agent Skill step 3b, and it is the only
variable between this arm and its pair — everything else about the two is identical.

Read `{SKILL_DIR}/references/screen-json.md` for the format before you write any of it.
You may also read `{SKILL_DIR}/references/errors.md` when the validator reports a code you
do not recognise. Those two files and the CLI are the only things you may open outside your
working directory.

```sh
node $YOSEGI screen generate screen.json --out ModerationScreen.stories.tsx --data-dir .yosegi
```

On validation errors no file is written and an array comes back with exit code 1. Apply the
entire printed array and re-run — do not clear the errors one at a time. Warnings appear
after the file is written and do not stop generation.

**Record every round.** Before each `screen generate` run, copy the screen JSON you are
about to submit to `attempts/NN-screen.json` (`01`, `02`, …), and write that run's output —
the validation errors, or the warnings on the run that succeeded — to `attempts/NN-result.json`.
Leave the screen JSON you finished with at `screen.json`. The number of rounds is part of
what this experiment measures, so the record has to be complete.
