# yosegi-bench

Does handing an agent a component registry change what it writes?

One screen, four UI libraries, three host sizes, and arms that vary what the agent can see.
The screen, the component API, and the degree of divergence from the library are held
constant; the library, the host's size, and the agent's information are the variables.

Results and method: [`docs/`](./docs). Measurements are regenerated by the scripts here,
not typed in by hand. This is the harness `docs/benchmark.md` in the Yosegi repository
refers to; the numbers it quotes come from [`docs/RESULTS.md`](./docs/RESULTS.md).

The matrix is re-run on each Yosegi minor release, against the published package, and tagged
with that version. `RESULTS.md` keeps one section per round and no round's numbers are
overwritten; `git tag` lists what has been measured.

## The question

Yosegi's claim is that an agent writes better screen code when it can ask a registry what a
component takes than when it guesses. `docs/registry.md` in the Yosegi repository states the
payoff scales with how far the host has drifted from what an agent already knows — a host on
an unmodified library gains little. This repository is the attempt to put numbers on both
halves of that, on four libraries at once.

## Layout

```
docs/
  SPEC-SCREEN.md   the screen every arm builds — handed to all arms
  SPEC-STATIC.md   the static screen experiment E builds
  SPEC-IMPL.md     the page experiment F builds from an approved Story
  CONTRACT.md      the component API every host implements — handed to no arm
  RECIPE.md        how far the product layer diverges from its library
  SCALE.md         how the 80- and 240-component hosts are grown from the 20
  MEASURE.md       arms, scoring, and what the design does not establish
  RESULTS.md       the numbers
prompts/
  A1 A2 B G H      the verbatim prompt each arm ran with, and the disclosures
hosts/
  <lib>/ <lib>-m/ <lib>-l/          20, 80, and 240 components; one Bun workspace
                                    package each, for each of the four libraries
scripts/
  build-registry.sh   registry per host
  listing.sh          the bare export listing handed to arm A1
  gen-filler-<lib>.mjs  deterministic filler that grows a host to 80 or 240
  setup-arms.sh       one isolated working directory per (host, arm)
  setup-efg.sh        the same for experiments E, F, G, and H — by section
  verify-contract.mjs every host implements the same API — this must stay at 0 mismatches
  score.sh            typecheck each arm's output against its host
  score-gh.sh         the same for arms G and H
  score-ef.sh         the same for experiments E and F
  silent.mjs          mistakes that compile and are still wrong
  cost.mjs            how much text an arm has to read to learn the API
results/
  <host>/<arm>/       the arm's working directory and its emitted story
  raw/                tsc output, verbatim
  raw-v0.2.0/         the same, from round 1
  screenshots/        the rendered A1/A2/B screens (round 1; not re-run)
results-e/ results-f/ results-g/ results-h/
                      the later experiments, same shape
```

## Running it

```sh
bun install
bun run registry             # build a registry per host — verify-contract reads it
bun run verify-contract      # 20 components, 0 mismatching across 4 hosts
./scripts/setup-arms.sh      # isolate A1, A2, B
./scripts/setup-efg.sh E G H # …and E, G, H; F reads an approved B story, so it waits
# … run A1, A2, B, E, G, H …
./scripts/setup-efg.sh F
# … run F …
./scripts/score.sh           # A1, A2, B
./scripts/score-gh.sh        # G, H
./scripts/score-ef.sh        # E, F
node scripts/silent.mjs $(ls hosts)          # ARMS=G / ARMS=H for the other two
```

`bun run registry` and `bun run verify-contract` cover the four 20-component hosts. The
12-package figure `docs/RESULTS.md` quotes takes every size:

```sh
for h in hosts/*/; do ./scripts/build-registry.sh "$(basename "$h")"; done
node scripts/verify-contract.mjs $(ls hosts)
```

`.yosegi/` is not committed, so the registries are rebuilt rather than restored; the same
holds for the copies `setup-arms.sh` places in each arm's directory.

`YOSEGI_BIN` points the registry build at a local Yosegi checkout instead of the published
package. `scripts/cost.mjs` reads it the same way.

## Honesty

The hosts are synthetic and the divergence is applied deliberately. What that does and does
not license is written down in [`docs/MEASURE.md`](./docs/MEASURE.md#what-this-design-does-not-establish),
and it belongs next to any number quoted from here.
